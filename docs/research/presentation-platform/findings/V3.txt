##### V3-slidev-pipeline

SUMMARY:
I tried to refute the Slidev pipeline claims (B2, B6, B7) with a new 7-slide deck written from scratch, a Mermaid variant of it, and the same deck built with @slidev/cli 52.11.5. Playback used the real md.qft.org production build (dist), with ZIPs uploaded through the presentation library's file input. Mostly full Chromium (channel 'chromium'); the headless shell was used where stated.

The build-conversion route (B2-F2) held up. None of the six patches broke on 53.1.0 default, 53.1.0 with Mermaid, or 52.11.5 (Vite 7, where the router call is minified with double quotes). The Node converter and the esbuild-wasm Worker converter (1.5 s cold, 0.9 s warm; 7.9 s with Mermaid) both produced decks that reach ready on the real site. In them, navigation, v-clicks, code-line steps, KaTeX, the public image, scoped CSS, the slider and the Mermaid diagram all work, with 0 external requests.

The in-browser compiler route (B2-F3) is DOM-identical on the new deck (7/7) but only 4/7 pixel-identical:
- **Slide 2:** frontmatter `class: pt-6` gets no CSS rule.
- **Slide 6:** Shiki token colours differ.
- **Mermaid:** flagged as unsupported.

B2's fidelity tool compares normalised DOM only, outside the sandbox. "DOM-identical" must not be read as "pixel-identical".

Other findings:
- **B7-F6 ("0 external requests"):** wrong in full Chromium. The jsDelivr favicon link survives `fonts.provider: none` and is fetched.
- **detect.mjs router mode:** it labels the 52.11.5 default (history) build as hash.
- **Test harness:** B2's harness sends keys with `frame.locator('body').press()`, which does not reach the nested opaque frame on the real site; keys only arrived after a real click in the deck.

EXTRA FINDINGS:
 - No converter patch broke on any new input (53.1.0 default, 53.1.0 plus Mermaid, 52.11.5 / Vite 7). The router regex handles both backtick and double-quote minification.
 - B2's in-browser fidelity verdict 'identical' is DOM-only and taken outside the sandbox. A pixel diff on a new deck found a lost frontmatter 'class: pt-6' utility (the UnoCSS pass does not scan per-slide frontmatter class) and different Shiki token colours, both invisible to the DOM comparison.
 - Slidev renders Mermaid inside a ShadowRoot; probes using document.querySelectorAll('svg') report a false 'Mermaid did not render'.
 - On the real site, Playwright's frame.locator('body').press() (used in B2's tests) does not deliver keys to the nested opaque-origin deck. Keys arrive only after a real pointer click in the deck. Real users must click the deck before arrow keys work.
 - Wasm conversion time scales with the module graph: 7.9 s and a 10 MB HTML for a deck with one Mermaid block, against 0.9-1.8 s for small decks.
 - detect.mjs reports routerMode 'hash' for a default (history) 52.11.5 build.
 - B7-F6's '0 external requests' misses the default jsDelivr favicon link, which full Chromium fetches; chrome-headless-shell does not fetch favicons.
