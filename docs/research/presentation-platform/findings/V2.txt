##### V2-reveal-pipeline

SUMMARY:
Out of sample, "Tier 1" works much less often than the published numbers suggest. I ran 8 testable decks with all external network blocked, through both the B7 harness player and the production site. B7 inline-deck fully passes 3 of 8, and 1 more works with a defect (an inline onclick button does nothing), so 4 of 8 are usable. A2 wrap-reveal passes 1 of 8. Both adapters handle the AI-made decks (n1, n2) well. They fail on ES modules, external Markdown (this deck reaches "ready" but is empty), 3.x plugin loading, and asset references they do not rewrite (an image in inline Markdown, data-src, data-background-image). The player treats any failed resource as fatal, which turns that last group into hard failures. A2 has no CDN mapping, so every CDN deck fails under it.

Input problems: the baseline decks r1, r1b and r2 are empty folders, so I wrote two substitute CDN decks and used B1's extmd6/esm6 in place of r2. n3 is not a deck: it has no HTML file and its css/js/code folders are empty.

Claims:
- Confirmed, with caveats: V2.1, V2.2, V2.3.
- Confirmed: V2.5, V2.7, V2.8 and V2.9. V2.7 and V2.8 also hold on new inputs.
- Partly refuted: V2.4. The AI-made corpus deck does not use RevealMath with katex.local, and it plays fine when inlined by B7 or A2.
- Partly reproduced: V2.6. My in-place swap timings agree with the claim; my reload timing probe failed, so that number is unverified.
- Mixed: V2.10. B6's 13 cases pass, but only 5 of my 8 new sub-cases behave well. One of the failures loses data: a truncated whole file with a bare "..." line is applied.

Browsers: H and S results were the same in full Chromium (channel 'chromium') and in chrome-headless-shell, except for one error message noted under V2.1. All servers I started are stopped. Another Chromium process that was already running is not mine and was left alone.

EXTRA FINDINGS:
 - The corpus baseline decks corpus/baseline/r1-single-html-cdn, r1b-single-html-cdn-5x and r2-multifile-local are empty folders, and corpus/naive/n4-reveal-markdown is empty too. Any report figure that claims to use them should be checked.
 - Treating 'ready' as a pass criterion is unsafe: extmd6 reaches 'ready' and 'Playing locally' with an empty deck when the external Markdown is blocked. B1's SW run of math-katex-default reaches ready with 0 KaTeX.
 - The player's rule that any failed resource is fatal turns a single unresolved image (for example one inside an inline Markdown textarea) into a whole-deck failure. Both adapters hit this on classic4.
 - B7 inline-deck does not convert inline on* handlers; it only reports the hazard. A2 converts them but has no CDN map. A merged adapter would need both, plus rewriting of data-src, data-background-image and Markdown-embedded images, and url()/@import in local CSS.
 - A2's E5 feature probe reads slide backgrounds wrongly (rgba(0,0,0,0) and none, also in A2's own JSON). The backgrounds do work, as shown by e5d through Reveal.getSlideBackground.
 - B1 notes describe corpus-n1 as 'RevealMath.KaTeX with katex.local'. The deck actually calls renderMathInElement on vendored KaTeX.
 - The SW player-origin prototype needs sandbox 'allow-scripts allow-same-origin allow-popups allow-modals allow-popups-to-escape-sandbox' on a second origin. That is a significant security trade-off compared with today's opaque allow-scripts sandbox, and the report should say so.
