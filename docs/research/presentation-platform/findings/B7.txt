##### B7-ai-authoring

SUMMARY:
The hand-off fails today because the site accepts none of the shapes AI tools naturally produce: 0 of 12 tested shapes play, 3 are silently imported as the wrong thing, and a `.html` file cannot be opened at all.

The natural Reveal.js answer is one HTML file loading reveal.js 4.x/5.x from jsDelivr or cdnjs (88.8% of jsDelivr reveal.js requests are still pre-6). A small browser-side adapter fixes this in the existing sandbox: a CDN-to-bundled map with version coercion to 6.0.2, a RevealMath shim and a `history.replaceState` guard. With it, 3 of 3 real lecture decks and 5 of 5 Reveal ZIP shapes played with zero network requests. `hash: true` is otherwise fatal.

Slidev always needs a build. Coding agents, Claude chat (npm allow-listed) and ChatGPT Work can run one; ChatGPT Chat, Gemini and consumer Copilot cannot. A stock project needs only two headmatter lines plus `--base ./` to build portably (install 43 s, build 6 s here). Whether the player can run that multi-file build is untested.

Agent Skills are the cross-vendor channel (46 clients, Claude Free included); a static site can serve one via `/.well-known/agent-skills/index.json`.

Drafted and tested: a 191-word Reveal prompt, a 197-word Slidev prompt, a SKILL.md outline, and a paste-back report format (`qft-deck-check/1`) with schema and working prototype.

Not verified: any third-party model end-to-end; Claude's sandbox Node version; ChatGPT Chat's current npm access. Rankings are judgments built on these measurements.

RECOMMENDATIONS (10):

[R1] (effort M; impact high) Accept the natural Reveal shape: open, drop and paste a single HTML (and index.html ZIPs) through a CDN-to-bundle adapter
   WHY: This is what every chat tool emits and the only thing Gemini and Copilot can emit. The prototype took Reveal shapes from 0 of 6 to 6 of 6 and played 3 of 3 real decks in the unchanged sandbox with zero network. Needs: URL map for reveal.js/KaTeX on jsDelivr, unpkg, cdnjs (v3-v6 layouts) coerced to the bundled 6.0.2; RevealMath shim; inlining of relative files; entry detection that prefers index.html over README.md and strips one enclosing folder; `.html` in the file picker; a paste box.
   RISKS: Version coercion was proven on only three decks; unusual plugins or 3.x APIs may break. The adapter must only ever inject site-bundled files, never fetch. Prototype misses cdnjs v6 `plugin/<name>/plugin.js` paths.

[R2] (effort S; impact high) Guard the History API in the player bootstrap and stop killing the deck on the first non-fatal error
   WHY: `hash: true` is in every sampled deck and throws at start-up in an opaque blob document. A 5-line try/catch around replaceState/pushState fixed it. One missing optional library currently blanks the stage; report it instead where possible.
   RISKS: Relaxing the error policy could leave a half-working deck on screen; keep CSP violations visible in the report.

[R3] (effort M; impact high) Emit a `qft-deck-check/1` report for every import, including rejected ones, with a Copy-for-AI button
   WHY: Only the site can see run-time errors and CSP violations. The prototype's reports are 483-2,078 characters, name file and line, give one imperative fix per item, list what the site already handled, and state the exact reply shape. Reuse the same codes in the CLI checker.
   RISKS: Static heuristics give false positives (a currency $ triggered a math warning once). Keep evidence snippets short so no lesson text leaks into chats unintentionally.

[R4] (effort S; impact high) Replace the long prompts with short profiles and add a Reveal.js choice to the AI dialog
   WHY: Current prompts are 849 and 454 words and there is no Reveal prompt at all. The drafted 191-word Reveal and 197-word Slidev prompts fit any chat box; their technical lines were executed here. Publish the detail at stable URLs (/ai/reveal.md, /ai/slidev.md, /ai/check-codes.md) instead of in the prompt.
   RISKS: The Reveal prompt is only safe to publish after the adapter and history guard ship. Prompts were not trialled on ChatGPT, Gemini or Copilot. Long decks may hit chat output limits.

[R5] (effort M; impact high) Publish an agent skill `qft-deck` with a zero-dependency checker and packer, discoverable from the repo and from the site
   WHY: Agents load skills automatically and can self-correct before delivering; this replaces the un-runnable VERIFY step. Put it in `skills/qft-deck/` (for `npx skills add renphysics/md.qft.org`), serve `/.well-known/agent-skills/index.json` plus a ZIP (for `npx skills add https://md.qft.org` and for upload to Claude), add `/llms.txt` and a short AGENTS.md block.
   RISKS: Description must stay within claude.ai's 200-character limit (draft is 191). The checker must be kept in step with the web checker; share one rule source.

[R6] (effort S; impact medium) Fix detection order and error wording now
   WHY: Cheap and independent of architecture: check for a build before calling a ZIP 'source'; do not tell Reveal users to use the Slidev packer; never import README.md as the document when an index.html is present; replace the repository path with a URL; mention `.html` in the open-file message.
   RISKS: None significant; add tests for the 12 corpus shapes.

[R7] (effort L; impact high) Define the Slidev contract as a standard build: `routerMode: memory` (or hash), `fonts.provider: none`, `slidev build --base ./`, source alongside dist
   WHY: Verified to give an offline, location-independent build without the bespoke starter, Vite profile or packer. The checker can read the router mode from the bundle and name the one-line fix. Update all Node statements to 22.22+.
   RISKS: The current player needs one self-contained HTML; unless it learns to run a multi-file build, the packing step merely moves into the skill's script. That feasibility was not tested by this task.

[R8] (effort L; impact medium) Make revisions round-trip: deck id and revision inside the file, stale-copy warning, slide-level copy and paste with stable ids, folder drop
   WHY: Keeps site and AI in sync after browser edits: the site stores the authored source and derives the playable form; exports stamp a revision; an incoming file based on an older revision triggers a warning and a diff. Stable slide ids replace slide counting, a failure a real lecturer reported. Folder drop works in all browsers; write-back only in Chromium.
   RISKS: Models may drop the meta line; treat that as a new deck rather than overwriting. A shared file shares its id.

[R9] (effort M; impact medium) Offer a template repository whose GitHub Action builds Slidev and attaches the ZIP
   WHY: The only Slidev route for people without Node whose AI cannot build (Gemini, Copilot, ChatGPT Chat), and a natural fit for cloud coding agents, which all work on GitHub repositories.
   RISKS: Requires a GitHub account, a real hurdle for non-developers. Not prototyped here.

[R10] (effort S; impact low) Do not build an MCP or WebMCP surface yet
   WHY: Shell-capable agents gain nothing over a CLI plus skill; chat connectors need a hosted server the static site does not have; WebMCP is still an origin trial.
   RISKS: Revisit if WebMCP ships; it could let in-browser agents push a deck and read the report without copy-paste.

 - Is ChatGPT Chat's container able to npm install and return ZIPs this month? The two 2026 reports disagree and OpenAI publishes no changelog.
 - How often do ChatGPT- and Gemini-written decks use inline on...= handlers, MathJax, Chart.js, Plotly or Three.js? My real sample is five decks, none from those models; this sets the size of the bundled allow-list and whether to auto-rewrite inline handlers.
