##### B1-revealjs

SUMMARY:
Reveal.js today has three incompatible file layouts (3.x, 4.x/5.x, 6.x); 6.0.0 (2026-03-11) moved plugins to dist/plugin/<name>.js, so 4.x/5.x-style paths die on 6.x with "RevealMarkdown is not defined". Pinned CDN URLs still work; unversioned ones work on jsDelivr only through a per-file version mix and are dead on unpkg/esm.sh.

Tested with the site's real player code (Chromium 158): every standard Reveal ZIP is rejected or misrouted, and even a fully inlined deck is killed by ordinary behaviour: hash:true with an id-less first slide (SecurityError in history.replaceState at startup), pressing F, pressing S, Google-Fonts themes, and the math plugin. A small shim plus a non-fatal error policy fixes the first three on 4.x-6.x.

Inlining into one blob document cannot run plugins or math that load files relative to their script (menu, copycode, chalkboard, katex.local). A service-worker prototype on a second origin played all 13 test decks unmodified, including speaker view and ?print-pdf.

Reveal's postMessage API and bubbling DOM events work inside sandbox="allow-scripts" and give a host slide state and speaker notes without a global. Blob URLs accept #/h/v/f but no query string.

Live edit: buffered reload with hash restore takes 170-250 ms and is always correct; a keyed section swap plus Reveal.sync() takes 20-30 ms. A detector prototype recognised 36/36 decks, picked the entry file and the version.

Firefox and Safari were not testable. One environment artifact (double slashes collapsed for Chromium) is documented.

   SOURCES: https://github.com/hakimel/reveal.js/releases

RECOMMENDATIONS (11):

[R1] (effort S; impact high) Make the player survivable for Reveal: non-fatal errors after ready, plus a compat shim
   WHY: Three of the four things that kill an ordinary deck (replaceState at startup, F, S) disappear with a 2.2 KB shim, and the fourth class (late uncaught errors, CSP reports) should become a warning instead of removing the frame. Verified on 4.6.1, 5.2.1 and 6.0.2 in the real chain. Also strip or neutralise remote @import before loading.
   RISKS: Relaxing the fatal-error policy can leave a half-working deck on screen; keep startup failures fatal and show later errors as a dismissible notice. The shim patches History, requestFullscreen and window.open inside the sandbox only. Firefox and Safari behaviour untested.

[R2] (effort M; impact high) Recognise Reveal decks on upload (ZIP folder or single HTML) and replace the Slidev-specific errors
   WHY: Today every Reveal ZIP gets a Slidev message or lands in the Markdown importer. The detector prototype classifies a folder in under 5 ms, picks the entry file among up to 33 HTML files, reads the version and names concrete problems (4.x paths on 6.x, missing files, unpinned CDN, external Markdown, math on a CDN).
   RISKS: Ties between several decks in one ZIP need a chooser. Heuristics were tuned on 39 samples; keep a manual override.

[R3] (effort L; impact high) Give decks a real URL space: a service-worker player on a second origin
   WHY: It ran all 13 test decks unmodified, including the cases inlining cannot do (third-party plugins, katex.local, external Markdown, ES modules, 3.x dependency loader, speaker view, ?print-pdf), and needs no History shim. The worker can add a CSP that blocks outside network access. If a second origin is not acceptable, the fallback is a rewriting bundler plus a runtime URL resolver, which is larger and will always trail the plugin ecosystem.
   RISKS: Needs a separate origin (subdomain or another Pages site) and allow-same-origin towards it; decks share that origin's storage; popups and self-navigation are possible exfiltration paths; service-worker lifecycle and Safari private mode; Cache Storage quota. None of these were evaluated here.

[R4] (effort M; impact high) Vendor reveal.js 3.9.2, 4.6.1, 5.2.1 and 6.0.2 and rewrite reveal CDN URLs to the local copies
   WHY: Chat-made decks reference CDNs (the corpus sample pins jsDelivr 5.2.1) and the sandbox allows no network. Mapping any reveal.js CDN URL to a vendored major also repairs rotten references (unversioned unpkg, 3.x paths, double slashes). Cost is 8.96 MB raw, 4.74 MB gzip, fetched only when a deck needs it.
   RISKS: Serving 4.6.1 for a deck pinned to 4.3.1 can change behaviour slightly. Other CDN libraries (KaTeX, MathJax, highlight themes, Google Fonts, Chart.js) need a separate decision: vendor a few, or offer a per-deck allowlist switch, which leaks the viewer's IP to the CDN.

[R5] (effort M; impact high) Live editing: buffered reload with position restore first, keyed in-place swap second
   WHY: Reload plus blob-URL fragment (and setState for 3.x fragments) is engine-agnostic, always correct and costs 170-250 ms (about 470 ms with 8.7 MB of inline media); hiding the new frame until ready avoids a blank flash. The keyed section swap with Reveal.sync() gives 20-30 ms feedback for pure slide-content and CSS edits.
   RISKS: In-place swaps drop listeners attached by deck scripts and need per-plugin re-rendering; restrict them to decks without custom scripts in the edited slides and fall back to reload otherwise.

[R6] (effort M; impact medium) Relay Reveal's postMessage protocol through the runner and use it in the host UI
   WHY: With postMessageEvents switched on remotely the host gets slide index, progress, total slides and speaker notes as JSON, and can drive slide(), setState() and follow-the-cursor without touching deck code. Bubbling DOM events cover decks without a global.
   RISKS: Messages come from untrusted deck code and must be validated as data. Several Reveal instances on one page all react to one command.

[R7] (effort S; impact high) Write an AI prompt and offer a starter ZIP built on vendored reveal 6.0.2
   WHY: Models trained on 3.x-5.x emit old paths; the 6.x path table is short, and revealjs.com now publishes llms.txt. A starter ZIP with dist/ and a template removes CDN and version guessing, and the prompt can ask for local dist/ paths or exact version pins.
   RISKS: Users will still upload decks made elsewhere, so detection and repair remain necessary.

[R8] (effort S; impact medium) Accept single self-contained HTML decks directly
   WHY: A pandoc --embed-resources deck already plays in the existing sandbox in 271 ms; Quarto embed-resources output uses the same mechanism. Only the upload path refuses it.
   RISKS: Embedded decks still fetch MathJax or Google Fonts unless the author embedded them; these must degrade to a warning, not a fatal error.

[R9] (effort S; impact medium) PDF export through print view inside the sandbox
   WHY: view:'print' as an init override produces the paged layout on 5.x and 6.x, and window.print() works from a frame with allow-modals. On a URL-space player the stock ?print-pdf also works for 4.x.
   RISKS: Upstream confirms PDF export only for Chrome and Chromium. 4.x in a blob document has no print option; allow-modals also permits alert and confirm.

[R10] (effort M; impact medium) Build a host-rendered presenter panel instead of relying on the built-in speaker view
   WHY: The built-in view cannot work from blob or opaque documents. getSlideNotes, getState and a second preview frame started at the next slide are enough for notes, timer and next-slide preview.
   RISKS: A second preview frame doubles memory for large decks. On a service-worker player origin the built-in popup works but needs allow-popups.

[R11] (effort S; impact low) Decide what narrow panes do
   WHY: 5.x and 6.x decks switch to scroll view at 435 px or less, which will surprise users in split or mobile layouts; scrollActivationWidth:null as an override keeps slide mode.
   RISKS: The override needs the init trap (UMD decks only) or a configure() call after ready.
