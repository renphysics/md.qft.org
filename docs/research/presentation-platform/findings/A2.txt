##### A2-audit-authoring

SUMMARY:
Audit of md.qft.org (commit 974fa5e) against the owner's goal, backed by a dozen scripted Playwright experiments on the production build.

Today the goal is met only through the site's own formats. "Create with AI" offers Markdown (833-word prompt) or Slidev (446 words); there is no Reveal.js option. Every standard Reveal.js output tried (multi-file ZIP, ZIP plus README, CDN single HTML, self-contained HTML) is refused or mis-opened. Slidev source and ordinary builds are refused; a lone slides.md is silently opened as a Markdown document.

The Markdown slide mode uses Reveal's core only as a pager: of 25 standard features, one works by other means (math), six partially, eighteen not at all. Reveal and Slidev syntax renders as literal text while "Check lesson" reports success. Browser editing works only for Markdown lessons, through a modal textarea; Slidev source is read-only.

The main opportunity: the existing opaque-origin player already runs a full Reveal.js 6.0.2 deck (vertical slides, fragments, auto-animate, backgrounds, highlight, markdown, search) after five mechanical rewrites that take 0.3 s without a bundler. What breaks is `hash: true`, the S and F keys, inline handlers and the CDN-only math plugin. Because Reveal source is its runtime, import, edit and replay need no compiler.

Reusable: the presentation sandbox, ZIP audit, path safety, revision review, checker heuristics, and already-shipped CodeMirror HTML/CSS/JS grammars. Slidev still needs a build (measured 11 s install, 4 s build, 1 s pack) or an in-browser compiler.

RECOMMENDATIONS (11):

[R1] (effort L; impact high) Add native Reveal.js project import and playback on the existing opaque sandbox
   WHY: E5 shows the current player already runs a full Reveal.js 6.0.2 deck after five mechanical rewrites (inline CSS/JS/assets, neutralise hash, convert handlers) done in about 0.3 s with no bundler; import 0.2-0.3 s, start about 0.5 s. Today every standard deck is refused. This is the shortest path to goals 2 and 3 for Reveal.js.
   RISKS: Decks that need eval, WebAssembly, workers, external iframes or remote media still fail under the sandbox CSP; base64 inlining adds about 33% size against the 24 MB HTML cap; handler conversion is imperfect for code using `this` or `return false`.

[R2] (effort M; impact high) Vendor Reveal.js and resolve CDN and legacy plugin paths locally, with a local KaTeX substitute for RevealMath
   WHY: The typical chat answer is one HTML file with CDN links. Reveal's math plugin is CDN-only and fatal in the sandbox. The 6.0 plugin path move makes unpinned URLs 404 (unpkg) or mix majors (jsDelivr). The site already ships reveal.js 6.0.2 and KaTeX 0.19.1.
   RISKS: Decks written for 3.x/4.x/5.x may not run on a vendored 6.x core; shipping several majors adds 1-4 MB each; the alias table needs upkeep; MathJax-specific macros will not render in KaTeX.

[R3] (effort S; impact high) Make the player tolerant: log instead of stop, and provide notes, fullscreen and history from the host
   WHY: Ordinary keys (S, F) and the default hash:true kill a deck because any uncaught error is fatal. This is a prerequisite for accepting third-party decks.
   RISKS: A deck in an error loop keeps running; needs a watchdog and a visible error log. Allowing inline handlers inside the opaque frame relaxes script-src-attr and needs a security review.

[R4] (effort M; impact high) Build an edit-and-replay workspace for multi-file projects
   WHY: Goal 4 is met only by a modal textarea for Markdown lessons. For Reveal.js, re-inlining and reloading the frame is enough. CodeMirror with HTML/CSS/JS grammars is already shipped; add a file tree, add/rename/delete, and a postMessage bridge that restores the current slide after reload.
   RISKS: Depends on the Reveal import path and on a project model that holds binary files; reload flicker on large decks; editing 1 MB vendor files should be blocked or read-only.

[R5] (effort S; impact high) Detect the engine on import and stop reporting success for the wrong thing
   WHY: A Reveal ZIP with a README opens the README as a 'lesson'; a lone Slidev slides.md opens as a Markdown document; website ZIPs are all called Slidev problems and point to a repository path with no link.
   RISKS: Heuristics (class="reveal", Reveal.initialize, Slidev headmatter keys, .vue files) can misclassify hybrid archives; keep an explicit 'open as…' override.

[R6] (effort S; impact medium) Make the checker dialect-aware and include runtime errors in the copyable report
   WHY: Check lesson passes decks full of Reveal or Slidev syntax. The copy-report-for-AI loop is the site's strongest AI-facing mechanism and should carry sandbox errors and CSP violations too.
   RISKS: False positives on legitimate text such as a paragraph starting with 'Note:'; report length for noisy decks.

[R7] (effort S; impact medium) Tolerant lesson import and prompt fixes
   WHY: One SVG or .py file aborts an import; the 150-entry limit is misreported; the placeholder projectId is valid and collides. Skip unknown files with a listed warning, generate a real UUID into the prompt at copy time, list allowed file types, and offer a single-message variant with inline demos for chat tools that cannot return a ZIP.
   RISKS: Silently dropping files can hide a missing dependency; the warning must be prominent and included in the check report.

[R8] (effort M; impact medium) Teach the Markdown mode the Reveal.js Markdown conventions behind an allowlist
   WHY: Notes, fragments, slide and element attribute comments, vertical separators and code line steps are what 'powered by reveal.js' implies and what models write from habit; supporting them removes most of the 108-word slide-syntax section of the prompt.
   RISKS: Creates a second, partial Reveal path beside the native import; attribute allowlisting must not reopen HTML injection; print and overflow checks need rework for fragments.

[R9] (effort L; impact medium) Unify lessons, Reveal projects and Slidev packages in one project model and store
   WHY: Two unrelated IndexedDB databases exist; packages are immutable blobs with no identity, diff or recovery; lesson projects allow only eight text extensions and four raster types. A manifest with an engine field, per-file records including binaries, line diff (cleanupDiff exists) and shared revision logic serve all three.
   RISKS: Migration of existing drafts and saved packages; browser storage quotas for media-heavy decks; identity for projects that arrive without a manifest.

[R10] (effort M; impact medium) For Slidev, publish the packager as a one-line tool that applies the portable profile itself
   WHY: The repo's packager fails on a default Slidev build (Google Fonts) and must be copied with three sibling files. Machine cost is small (11 s install, 4 s build, 1 s pack); the obstacle is knowing the recipe. In-browser compilation is a separate XL item for the prototype agents.
   RISKS: Still unusable for chat-only users; overriding a deck's headmatter can change its look; Slidev releases move fast (53.1.0 today).

[R11] (effort S; impact medium) Fix the two Reveal integration defects found
   WHY: The page query string can break the slide preview (?view=scroll, ?print-pdf), and Save PDF is refused for the site's own quantum example because of a 4-5 px .katex-display measurement.
   RISKS: Low; relaxing the overflow test must still catch genuinely clipped equations.

OPEN QUESTIONS:
 - Should the site's Markdown dialect remain a third format, or converge on Reveal's Markdown conventions so one mental model serves both paths?
 - Is downloading public library files (Reveal plugins, KaTeX, fonts) at import time compatible with the owner's 'nothing is sent to a server' promise, or must everything be vendored (roughly 1-4 MB per Reveal major)?
 - Which runtime errors should stop a third-party deck? Today every uncaught error, rejection and CSP violation does.
 - How should a standard project without a manifest get a stable identity for revision review: a sidecar file added on export, a content hash, or the file name?
 - Is a presenter view required? The sandbox forbids pop-ups, so the host would have to render notes itself.
 - How should PDF export work for arbitrary decks inside an opaque sandbox (window.print needs allow-modals): print from the exported standalone file, or a host-side print view?
 - Is the owner willing to add 'wasm-unsafe-eval' (and possibly blob: script sources) to the app-shell CSP if an in-browser Slidev compiler needs it?
 - Can the chat products teachers actually use complete the Slidev build in their sandboxes (128 MB download, 573 MB node_modules)? Not tested here; vendor documentation and reports disagree or are silent.
 - Do current chat models emit Reveal 6-style paths, pinned CDN versions and ZIPs reliably? The shared naive-deck corpus should answer this.
 - What storage limits apply if the 30 MB lesson and 60 MB package caps are raised for video-heavy decks?
